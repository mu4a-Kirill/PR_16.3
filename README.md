## Вывод о проведенном тестировании

### Общие результаты

В ходе выполнения работы были разработаны модульные тесты для следующих компонентов приложения:

1. **Модуль авторизации** – проверка успешного входа существующих пользователей и отклонения неверных данных.
2. **Модуль CAPTCHA** – проверка появления капчи после трёх неудачных попыток, корректности кода, обновления, сброса после успешного входа.
3. **Модуль регистрации** – проверка обязательности полей, уникальности логина, успешного создания нового пользователя.

### Результаты выполнения тестов

Все тесты были запущены в среде Visual Studio 2022 с использованием `MSTest`. Результаты:

### Причины успешного выполнения тестов

1. **Корректная реализация бизнес-логики** – методы `Auth()` и `Register()` правильно обрабатывают все проверки:
   - Проверка на пустые поля логина и пароля.
   - Проверка существования пользователя в БД.
   - Счётчик неудачных попыток и активация капчи после трёх ошибок.
   - Сравнение введённого кода капчи с сгенерированным.
   - Проверка уникальности логина при регистрации.

2. **Изолированность тестов** – каждый тест создаёт собственный экземпляр окна (`LoginWindow`, `RegistraciyaWindow`), что исключает влияние предыдущих тестов на последующие.

3. **Стабильная тестовая среда** – база данных `CinemaBD` содержит предопределённых пользователей (`ivanov`, `petrov`, `admin`, `mu4a`), что позволяет тестам предсказуемо проверять как успешные, так и неудачные сценарии.

4. **Чёткая спецификация требований** – тестовые сценарии (TC_AUTH_02, TC_AUTH_03, TC_REG_01–03) были формализованы, что позволило написать точные проверки.

5. **Наличие вспомогательных методов** – публичные методы `GetCurrentCaptcha()`, `RefreshCaptcha()`, `ResetFailedAttempts()` обеспечили полный контроль над состоянием капчи из тестов.

### Заключение

Разработанное приложение и набор модульных тестов демонстрируют, что функционал авторизации, регистрации и защиты от подбора пароля (CAPTCHA) работает в соответствии с требованиями. Все тесты пройдены успешно, что подтверждает корректность реализации и готовность модуля к интеграции в основное приложение.
